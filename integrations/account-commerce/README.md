# 灵笔收费系统：部署与验收

2026-10-13 已部署到 https://airai.world/lingbi/，当前为 `observe` 模式。真实用量进入账号系统，客户端不保存可消费余额。套餐购买和真实扣点尚未开放，不能把本次代码部署视为商业验收完成。

## 实现范围

- 独立科研点数资产、个人及团队账本、赠送/购买批次、到期优先消费、月度赠送和成员预算。
- 服务端商品定价、订单防重、预占、实际供应商用量结算、失败释放、部分成果计费和持久化结算重试。
- 用户确认付款账户、模型来源和点数上限；自带密钥不会静默切换为平台付费模型。
- 支付验签、服务端查单、退款批次追溯及财务审核接口；会员与用量、订单、消费记录、开票申请页面。
- 套餐附件容量及文献本数量检查。当前容量计量覆盖附件原文件；对象存储、衍生产物全量容量及账户资源归属仍需独立验收。

价格和服务费由 `lingbi_catalog.py` 提供，供应商成本由服务端 `LINGBI_PRICE_BOOK_JSON` 配置。未定价模型禁止正式收费。旧钱包不按新比例转换。

## 上线条件

正式收费必须同时满足：采集满 7 天、成本对账通过、支付及退款验收通过、存储容量验收通过，并由运营将模式切换为 `enforced`。对应开关为 `LINGBI_COST_AUDIT_PASSED`、`LINGBI_PAYMENT_AUDIT_PASSED`、`LINGBI_STORAGE_AUDIT_PASSED`。不可为通过接口检查而设置这些生产开关。

本次部署服务器剩余磁盘不足 1GB，尚不能承诺课题组 100GB 存储；需扩容或接入对象存储。用户已有支付宝测试环境，但沙箱配置路径尚待确认。已有通用支付宝配置不能据此认定为沙箱配置；不得用不明环境的商户密钥执行付款或退款测试。

## 验证记录

- 17 项 Python 测试通过，包含独立 SQLite、实际 PostgreSQL 临时 schema、RSA/AES 支付通知验证和重复通知防重。
- TypeScript 用量与交付测试通过：实际 SSE Token、来源隔离、8 页并行 PPT、部分成功、失败无成果及结算失败重试。
- 完整 Next.js/服务端构建通过；目标文件类型和 lint 检查通过。
- 隔离端到端测试：真实账号及应用接口，测试供应商返回输入 21/输出 7 Token，报价上限 17 点、结算 3 点、释放 14 点；重复报价被拒绝且不重复扣款。测试供应商不是实际付费商户。
- 独立浏览器验证桌面和手机布局无横向溢出，取消确认不会执行任务。
- 尚未完成：真实支付宝沙箱到账/退款、微信渠道验收、连续 7 天供应商账单对账、实际容量验收及全量故障演练。

## 运维边界

生产签名和供应商密钥仅保留在服务器环境文件中，不进入 Git。账号系统是订单、会员和余额的唯一来源。结算重试文件仅存任务和资源元数据，不含提示词、用户密钥或登录令牌。

任务结算失败保留预占，不能直接释放。若进程在写入结算重试文件前终止，预占仍保留在账号数据库，需要核对供应商记录后人工处理；不能宣称此类孤立任务已自动恢复。有效期内跨套餐升级暂需人工按比例审核，不自动重复购买。财务接口默认不授权任何成员，须由服务端配置明确的财务成员白名单。

生产目录 `/opt/knowtrail/current` 指向本次发布目录，`/opt/knowtrail/previous-commerce-20261013` 保留上一运行版本。账号原文件备份位于 `/opt/account-entitlement/commerce-backup-20261013/`。回滚前应先暂停新任务，保留账本及待结算记录，不能回滚或清空消费数据。
